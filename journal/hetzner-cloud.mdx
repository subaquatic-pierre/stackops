## Overview

**Hetzner Cloud Infrastructure** is the backbone of CODATIVITY's operations — a single monorepo that defines and manages all infrastructure for deploying 17+ client applications. It is the single source of truth for server provisioning, Kubernetes cluster bootstrapping, application deployment, SSL termination, and traffic routing.

Every CODATIVITY client project — from Booking Clinic and Maven Platform to Luke Stays and The Craft Safari — runs on infrastructure defined in this repository. Changes to any application's Kubernetes manifests are automatically detected by ArgoCD and synced within minutes.

---

## Key Features

- **ArgoCD ApplicationSet:** Auto-generates Kubernetes Applications for every directory under `gitops/namespaces/*/` — zero manual config for new projects
- **Kustomize overlays:** Base templates shared across projects, with production overlays adding replicas, node selectors, and scheduling constraints
- **Dedicated workload isolation:** Production workloads use `NoSchedule` taints to prevent non-production pods from landing on production nodes
- **GitOps CI/CD:** Staging auto-deploys on tag push; production requires PR approval for gated rollouts
- **Slack notifications:** ArgoCD sends rich deployment status messages to the team
- **Dual-mode deployment:** Applications can run in Kubernetes or as bare-metal Docker via systemd (used for Maven ERP production)
- **Sealed Secrets:** Sensitive configuration encrypted at rest and safe to commit to Git

## Physical Infrastructure

CODATIVITY runs on three Hetzner Cloud bare-metal/VMs:

| Server | Role |
|--------|------|
| **cdt-control** | Kubernetes control plane + Nginx reverse proxy |
| **cdt-worker** | Kubernetes worker node running all containerized apps |
| **cdt-db** | Central database server (PostgreSQL, MongoDB, MySQL) |

This is a compact but powerful setup: two K8s nodes handle all compute workloads, while a dedicated database server keeps data isolated and performant.

## Layered Architecture

The infrastructure is built in five distinct layers, each managed by a different tool:

### Layer 1 — Ansible (OS Provisioning)

Ansible playbooks bootstrap the bare OS on each server: installing containerd, kubelet, and kubeadm. The control plane playbook runs `kubeadm init` with Flannel CNI, while worker playbooks run `kubeadm join` to attach nodes to the cluster.

### Layer 2 — Terraform (Cluster Management)

Terraform manages Kubernetes-level resources through the Helm provider. It creates the `argocd` and `sealed-secrets` namespaces, deploys ArgoCD and SealedSecrets via Helm charts, and applies node taints/labels for workload isolation (e.g., dedicated production node pools).

### Layer 3 — ArgoCD (GitOps Deployment)

An **ApplicationSet** auto-discovers every directory under `gitops/namespaces/*/` and generates ArgoCD Applications from them. This means adding a new project is as simple as creating its namespace directory — ArgoCD picks it up automatically. Applications are configured with self-healing and auto-prune, and ArgoCD sends Slack notifications on every sync.

### Layer 4 — Kustomize (Environment Overlays)

Each application follows a **base + namespace overlay** pattern. The `gitops/base/` directory contains shared Kubernetes manifest templates (Deployments, Services, ConfigMaps), while `gitops/namespaces/<project>/` overlays add environment-specific configuration — replica counts, node selectors, tolerations, and topology spread constraints for production workloads.

### Layer 5 — Nginx (Traffic Routing)

Nginx runs on `cdt-control` with 21 site configuration files in `sites-available/`. Each site config reverse-proxies to a Kubernetes NodePort service, terminating SSL via Let's Encrypt certificates. Configurations are synced to the control node via rsync.

## Tool Stack

| Tool | Role |
|------|------|
| **Terraform** | Kubernetes cluster management (Helm releases, namespaces, secrets) |
| **Ansible** | Bare-metal OS provisioning and cluster bootstrapping |
| **Kubernetes** | Container orchestration (kubeadm + Flannel CNI) |
| **ArgoCD** | GitOps continuous delivery with ApplicationSet auto-discovery |
| **Kustomize** | Per-environment manifest customization |
| **Helm** | ArgoCD and SealedSecrets installation |
| **SealedSecrets** | Encrypted Kubernetes secrets safe for Git storage |
| **Nginx** | Reverse proxy + SSL termination (Let's Encrypt) |
| **GitHub Actions** | CI pipelines in individual application repositories |
