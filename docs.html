    Technical Reference

    StackOps is a knowledge base for infrastructure, operations, and development workflows. It is organized as a hybrid cookbook and reference manual: goal-oriented playbooks sit next to conceptual deep-dives, all discoverable through search and tags.

    Browse by domain​

    Linux & Systems

    System configuration, common locations, command-line recipes, networking, and kernel.

    Terraform

    Getting started, state, modules, loops, secrets, testing, and team collaboration.

    Kubernetes

    Cluster operations, manifests, RBAC, Helm, EKS, node setup, and design patterns.

    Rust

    Ownership, async runtime, concurrency primitives, dynamic dispatch, Axum, WASM, and no_std patterns.

    Python

    Language internals, async patterns, object model, package management, and FastAPI production references.

    TypeScript

    Compilation model, JavaScript prototype chain, Node.js event loop, Next.js patterns, and tooling.

    Docker

    Container lifecycle, image management, Compose reference, and production project examples.

    AWS Cloud

    Identity, networking, operational playbooks, and common architecture patterns for Amazon Web Services.

    GitOps

    ArgoCD application management, progressive delivery, and GitOps deployment patterns.

    Databases

    PostgreSQL and MongoDB — user management, CRUD, backup/restore, and configuration.

    SRE & Observability

    Prometheus, Grafana, Loki, Mimir — architecture tradeoffs and incident management.

    Editors

    Vim and VS Code — configuration, keybindings, extensions, and workflow references.

    System Architecture

    Patterns, principles, and reference material for designing reliable systems.

    Agentic Engineering

    OpenCode configuration, Spec Kit workflow, custom agents, and Docker sandboxing.

    Content types​

    Documents are categorized by intent, not by hierarchy.

    • Actionable — goal-oriented playbooks with copy-paste commands. File names follow the pattern verb-noun-context.mdx.
    • Reference — conceptual explanations, architectures, and config locations. File names follow the pattern noun-context.mdx.

    Use the sidebar to expand a domain, or use the search bar to find a specific tool, command, or concept.
