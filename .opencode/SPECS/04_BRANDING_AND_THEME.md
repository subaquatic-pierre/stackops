# Branding & Theme Specification

## Brand Identity
- **Name:** StackOps
- **Tagline:** Software engineering through an operational lense

## Typography
- **Primary Font (Sans-serif):** `Inter`, `system-ui`, `sans-serif`
- **Code/Monospace Font:** `JetBrains Mono`, `monospace`

## Color Palette (Dark Theme Optimized)

### Surface (Backgrounds)
The design relies on a deep, layered dark theme rather than pure black or standard grays.
- **Surface 0:** `#09090b` (Main body background)
- **Surface 1:** `#0f1117`
- **Surface 2:** `#16181d` (Elevated cards/inputs)
- **Surface 3:** `#1c1f26` (Badges/tags)
- **Surface 4:** `#22252d`

### Accent Colors
- **Primary Accent (Green):** 
  - `DEFAULT`: `#22c55e`
  - `light`: `#4ade80`
  - `dim`: `#16a34a`
- **Secondary Brand (Blue):**
  - `DEFAULT`: `#3b82f6`
  - `light`: `#60a5fa`
  - `dim`: `#2563eb`

## Visual Language & UI Motifs
1. **Glow Orbs:** Large, heavily blurred colored circles positioned absolutely behind main content to create depth and focus (using `filter: blur(100px)`).
2. **Subtle Grids:** Backgrounds utilize a very faint grid pattern (`rgba(59,130,246,0.03)`) to reinforce the "technical/infrastructure" theme.
3. **Glassmorphism/Translucency:** Navbars and cards use semi-transparent backgrounds with a backdrop blur and a very subtle border (`rgba(255,255,255,0.06)`) to separate layers.
4. **Terminal Windows:** Interactive or decorative elements styled as terminal windows with the classic macOS red/yellow/green dots, a title bar, and syntax-highlighted monospace text.
5. **Gradients:** Text gradients (e.g., green-to-light-green) used sparingly for key headlines.

## Logo Definition
The logo is a stylized geometric representation of a "stack" or "tree" structure, invoking infrastructure and scaling. We will use a minimalist SVG approach, utilizing the primary accent color (`#22c55e`).

## Copywriting & Voice
- **Tone:** Technical, straightforward, and engineering-focused.
- **Rules:** Avoid "sales-y" marketing jargon (e.g., "Built for speed," "Everything your team needs"). Do not use overly enthusiastic or persuasive language. Use objective descriptions of architecture, workflows, and configurations.
- **Focus:** Emphasize the Technical Reference / Knowledge Base aspect of the project. The "Project Showcase" is a secondary feature and should not dominate the primary copy.
